# 静谧临床后台·图表与数据模块规范

本规范把参考图中的视觉语言转成可复用、可验证的图表系统。目标不是复刻某一张图，而是在经营、临床、排期、实验室和人员后台中稳定生成更多图表样式，同时保持数据真实、视觉一致、低焦虑且高密度。

## 1. 使用流程

生成任何图表前按以下顺序决策：

1. 写出这个模块必须回答的一个主问题，例如“最近 6 个月入院量如何变化？”而不是笼统地写“展示数据”。
2. 确认比较对象、时间粒度、单位、分母、目标、阈值、缺失值与数据新鲜度。
3. 在选择矩阵中选图表族；如果表格能更快回答问题，优先使用表格。
4. 区分普通序列色与业务状态色。只有真实状态或阈值才使用 Success、Warning、Critical。
5. 决定必要标注：标题、范围、单位、图例/直接标注、基准、数据来源、更新时间。
6. 同时设计 loading、empty、error、no-result、部分缺失和极值状态。
7. 为图表提供一段文本摘要和可访问的数据表或明细入口。

一个图表卡只回答一个主问题。多问题必须拆卡或使用明确的 Tab，不通过叠加更多坐标轴和图例解决。

## 2. 图表选择矩阵

| 业务问题 | 首选表达 | 可兼容变体 | 不应使用 |
|---|---|---|---|
| 随时间变化 | 折线图 | 小面积图、Sparkline | 环图、无时间顺序的柱图 |
| 多序列同单位趋势 | 2–3 条折线 | 小多图 | 不同单位共用单轴；默认双轴 |
| 离散周期比较 | 分组柱图 | 单序列柱图、目标背景柱 | 平滑折线伪造连续性 |
| 总量的真实组成 | 堆叠柱图 | 100% 堆叠柱、分段环图 | 互不相加的指标堆叠 |
| 类别排名/容量 | 水平条形图 | 进度条、Bullet chart | 类别过多的环图 |
| 单指标进度/达成 | 环形 KPI | 线性进度、Bullet chart | 仅为装饰的仪表盘指针 |
| 5 类以内构成 | 分段环图 | 100% 堆叠条 | 3D 饼图、超过 5 类的环图 |
| 日期与预约分布 | 月历 | 周历、日历热力格 | 折线图代替可操作日期 |
| 阶段与处理轨迹 | 垂直时间线 | 水平阶段条、资源轨道 | 用普通列表隐藏顺序关系 |
| 分布与密度 | 直方图 | 箱线图、点图 | 用柱图把连续区间当类别 |
| 两变量关系 | 散点图 | 气泡图（第三变量确有意义） | 用气泡大小装饰 |
| 高密度二维强弱 | 热力图 | 表格内色阶 | 彩虹色阶、只靠颜色读数 |

兼容扩展图表必须复用本规范的卡片、轴线、字体、色彩、Tooltip、状态与响应式规则，不能引入另一套“ BI 工具默认皮肤”。

## 3. 图表卡共享骨架

### 3.1 标准结构

    ChartCard
    ├─ Header
    │  ├─ Title + optional description/time range
    │  └─ Legend / filter / See all / more menu
    ├─ Plot
    │  ├─ axes/grid/marks
    │  └─ tooltip/selection layer
    └─ Footer（可选）
       ├─ total/benchmark/delta
       └─ source/updated time/detail entry

- 标准卡片圆角使用 `--ca-radius-card`；边框与阴影沿用全局 Card。
- 默认内边距 16px；大图 20px。卡间距 12–16px。
- 标题 14–16px、600–700；说明 11–12px，使用 `--ca-ink-3`。
- Header 最小高 40px，标题与右侧操作基线对齐；“查看全部”始终位于右上。
- 常规绘图区高度 220–300px；紧凑图 160–200px；首屏主图最多 320px，除专业工作区外不做巨型图。
- Footer 与 Plot 间使用 12–16px 间距或一条细分割线，不用大色块。
- 同一网格行中的图表卡尽量等高；不同复杂度通过内部留白而不是改变卡片语言解决。

### 3.2 标题与图例

- 标题直接写业务对象与度量，如“入院与出院量”，避免“数据分析”“趋势展示”。
- 副标题提供时间范围和聚合粒度，如“最近 6 个月 · 按月”。
- 2–3 个短序列使用顶部右侧图例；空间不足或名称较长时使用直接标注或移到 Plot 下方。
- 图例标记必须与图形一致：线用短线 + 点，柱用圆角色块，状态用圆点。
- 图例可交互时使用按钮语义，提供 hover、focus、selected、disabled；隐藏某序列后仍保留可恢复入口。

## 4. 视觉语法与 Token

### 4.1 坐标与网格

- 坐标轴文字 11–12px，颜色 `--ca-chart-axis`；数值使用 tabular numbers。
- 水平辅助线使用 `--ca-chart-grid`、1px 虚线或细实线；主图默认 4–6 条，不画密集方格纸。
- 只有精确的离散时间比较需要垂直辅助线；避免横纵网格同时过强。
- 零基线比普通网格深一级。柱图原则上从 0 开始；若截断必须明确断轴和原因。
- 绘图区左右至少保留 12px；Y 轴标签不与卡边贴合。
- 单位放在轴标题、卡片副标题或数值中，不能只藏在 Tooltip。

### 4.2 普通序列与语义状态

普通序列按固定顺序使用：Primary 品牌中点蓝 `#3E5ABD` → AI 紫 → Info 青 → 中性蓝灰。它们表示可区分的数据系列，不表示好坏。图表文字、数字、图例和轴标统一使用 Plus Jakarta Sans 400/500/600，并按字符回退中文字体。

业务状态使用固定语义：

| 状态 | 颜色 | 用途 |
|---|---|---|
| 完成/健康/达标 | `--ca-success` | 已完成、正常、满意、达标 |
| 信息/已排期/进行中 | `--ca-info` | Scheduled、Live、处理中 |
| 待处理/接近阈值 | `--ca-warning` | Pending、Under review、容量偏高 |
| 失败/危急/爽约 | `--ca-critical` | Critical、No-show、超阈值 |
| 主序列/当前选择 | `--ca-primary` | 主要指标、选中日期、焦点序列 |
| AI 建议 | `--ca-ai` | 洞察来源与建议，不代表风险等级 |

同一图内强色建议不超过 4 种。类别超过 5 个时优先改用排序、分组、小多图或表格；不要扩展成彩虹配色。

### 4.3 渐变、透明度与圆角

- 默认使用纯色。主序列柱体可复用品牌同色系渐变 `#4C6CDA → #3E5ABD → #3145A7`，但方向必须顺着柱体长度并保持稳定，不得改变数值读法。
- 折线、点、坐标轴、文字和细进度条使用纯色 `#3E5ABD`，不把按钮的横向渐变硬套在线条或文字上。若分段色块代表实际组成，必须提供图例或直接标注。
- 面积填充透明度保持 6–14%；多面积叠加时优先取消填充。
- 柱图外端圆角 6–10px；堆叠柱只给最外端圆角，内部段不单独做胶囊。
- 折线宽 2–2.5px；点 5–7px，白色或当前表面填充并使用 2px 序列色描边。
- 环图轨道使用 `--ca-chart-track`；环宽约外径的 10–16%，端点可圆角。

### 4.4 数值格式

- 同一指标统一小数位。计数默认整数；比例 0–1 位小数；时长明确 min/h/d；金额包含币种或符号。
- 千位分隔、缩写和单位保持一致，例如不要在同一图混用 `1,248` 与 `1.2k`。
- 百分比必须说明分母；趋势百分比必须说明比较周期。
- 数据标签只标关键点、最新值、峰谷、阈值或用户选中点。全量标签重叠时使用 Tooltip 和数据表。

## 5. 图表族规范

### 5.1 圆角分组柱图：周期与双序列比较

适用：入院/出院、计划/实际、申请/完成等同单位离散周期比较。

- 每组 2–3 根柱，组内间距 4–8px，组间间距 20–32px。
- 柱宽 20–32px；数据点少时可增至 36px，但不做粗重矩形墙。
- 使用蓝 + 紫等普通序列色；只有序列本身是业务状态时才用状态色。
- 可用 100% 的浅色“容量背景柱”表达上限/目标，前景柱表达实际值；必须在图例或说明中写明目标含义。
- 主序列可使用统一品牌蓝渐变，其他序列保持纯色；保证从柱顶读取高度。打印、深色主题或对比不足时退化为 `#3E5ABD` 纯色。
- 序列超过 3 个或周期超过 12 个时，改用折线、小多图或水平滚动。

### 5.2 同色阶堆叠柱：真实组成与日内负荷

适用：每日总量由明确阶段、班次或科室组成，且各段可相加。

- 使用同一色相 3–4 个明度层级，减少视觉焦虑；图例顺序与堆叠顺序一致。
- 每根柱的总高度回答“总量”，内部段回答“构成”。若只需总量，不要用装饰性分段。
- 段值太小无法交互时通过 Tooltip、表格或展开详情提供，不隐藏数据。
- 负值、互斥指标或不同单位严禁堆叠。
- 图下可附“总量 + 与基准对比”的紧凑 Footer，趋势箭头使用 Lucide `TrendingUp` / `TrendingDown`，并附文字。

### 5.3 平滑双折线：趋势与波动

适用：2 个同单位、同时间粒度指标的趋势比较。

- 线宽 2px，点径 5–6px。推荐 Primary/AI 或 Purple/Warning；Warning 只有该序列本身具有警示语义时使用。
- 平滑只使用 monotone 曲线，不能越过真实点产生不存在的峰谷；周期离散或数据稀疏时优先直线段。
- 默认标记首值、末值、峰谷或选中点；避免每个点都贴数字。
- 缺失值显示断线或空心缺失标记，不跨越缺失区补线。预测段用虚线并标“预测”。
- 不同单位应拆成上下对齐的小多图；确需双轴时必须标清左右单位、轴与序列颜色，并在交付中说明理由。
- 直接标注优先于长图例；Tooltip 显示时间、各序列值、单位、相对变化和数据状态。

### 5.4 环形 KPI：单指标达成与阈值

适用：床位占用率、平均住院日目标、再入院率、满意度等单指标进度。

- 单环外径 64–88px，环宽 7–10px；中心放主值，标签、分母/目标和趋势位于右侧。
- 2×2 网格适合 4 个指标；单卡最多 4 环。超过 4 个改用 KPI 列表或 Bullet chart。
- 环从 12 点方向开始，顺时针；轨道保持中性浅灰。
- 颜色由指标语义与阈值决定，不因百分比高就自动变绿。例如再入院率越低越好，必须按目标方向判断。
- 100% 不得溢出成多圈；超过目标时显示 `100%+`、超额文本或独立差值，不伪造角度。
- 中心值之外必须给出指标名称、目标/分母、趋势方向和时间范围。

### 5.5 分段环图：少量类别构成

适用：预约状态、订单状态、收入构成等 2–5 个互斥且合计为总量的类别。

- 环外径 148–196px，环宽 18–26px；段间留 4–8° 视觉间隔。
- 中心显示 `Total`、总数/金额和必要单位；右侧使用 2 列或垂直图例展示类别名与精确值。
- 类别顺序按业务流程、严重性或数值排序，跨页面保持稳定。
- 状态型构成使用全局语义色；普通构成使用普通序列色，避免把普通类别误读为异常。
- 单段小于约 3% 时不要强行在环上标字；保留图例、Tooltip 和文本表。
- 类别超过 5 个、差异很小或需要精确比较时，改用水平条形图。

### 5.6 水平容量条：排名、负荷与阈值

适用：科室容量利用率、人员负荷、品类完成率、SLA 达成率。

- 标签左对齐，精确值右对齐，中间轨道自适应；整行高 28–36px。
- 轨道高 6–8px，圆角 999px；使用中性轨道 + 单色前景。
- 默认按数值降序；若业务流程顺序更重要，保留流程顺序并说明。
- 只有存在明确阈值时才使用绿/黄/红分段。阈值必须来自业务规则并可在 Tooltip/说明中查看。
- 普通排名使用同一主色或有序同色阶，不能每行随机一种高饱和色。
- 值超出范围时明确显示超额，不裁切数字；缺失值显示 `—` 和原因。

### 5.7 月历 + 汇总条：调度与日期状态

适用：预约、排班、资源预订、每日事件量。

- 月标题位于左上，月份切换/今天/视图切换放右侧；星期头与日期格保持固定 7 列。
- 日期格桌面最小 44px 高；选中日使用 Primary 浅底 + 1px 边框，不使用纯蓝大色块。
- 今天、选中、范围、不可用、含事件、冲突是不同状态，必须有形状/文字线索，不能只靠相近色。
- 月外日期降低对比但仍可读；不可用日期不可完全消失。
- 下方汇总条可放 Today / Pending / Confirmed 等 3 个指标，使用文字 + 数字 + 语义色，保留分割线和一致对齐。
- 日期内容多时显示 1–3 个事件点/短标签和“+N”，点击进入 Popover/Drawer；不得把超出事件直接删除。
- 窄屏优先改周视图、横向滚动或日期列表，并保留全部事件入口。

### 5.8 状态时间线：流程轨迹与样本节点

适用：样本流程、订单履约、患者就诊、审批与工单轨迹。

- 使用 1px 中性竖线连接 10–12px 节点；节点颜色表达当前状态，已完成节点可实心，未来节点使用中性空心。
- 每个节点至少包含阶段名、主要说明、时间；可选地点、责任人、耗时和异常原因。
- 文本与节点间距 12px，节点间垂直间距 16–24px；长说明最多显示两行并提供完整查看。
- 当前节点可用 Primary/Info，待复核用 Warning，失败/超时用 Critical；不能把所有历史节点都涂强色。
- 超时必须同时显示“超时 N 分钟/小时”等文字。点击节点打开同主题的 Popover/Drawer。
- 时间线过长时显示最近节点 + 明确的“查看全部”，不能静默截断。

### 5.9 AI 洞察组：解释与下一步

这不是传统统计图，但可与图表组成数据叙事。适用：负荷提醒、周转改善、质量建议。

- 在同一卡中堆叠 2–4 条洞察，每条使用极浅语义底或统一白底 + 左侧语义标识。
- 每条包含 Lucide 图标、类型/风险、结论、证据、更新时间和下一步操作。
- AI 紫色只表达“由 AI 生成”；真实风险仍使用 Warning/Critical 文案和状态色。
- 图标默认 16px、`stroke-width: 1.8`、`currentColor`；不得使用 Emoji 或手工 SVG。
- 不把建议写成自动结论；高风险建议必须保留人工确认入口。

### 5.10 兼容扩展族

以下图表可在遵守共享视觉语法时使用：

- **Sparkline：** 放在 KPI 内显示短趋势，48–96px 宽，不显示复杂坐标；旁边必须有当前值与变化文本。
- **Bullet chart：** 表达实际值、目标和区间，比环形 KPI 更适合精确比较；目标使用 2px 垂直线。
- **100% 堆叠条：** 比较多组构成比例；各组总量差异很重要时同时给出总量。
- **热力图：** 适合星期 × 时段、科室 × 指标；使用单色连续色阶并显示精确 Tooltip/表格。
- **直方图/箱线图：** 适合时长、年龄、检测值分布；明确样本量、分箱规则、中位数和异常值定义。
- **散点图：** 适合相关性与离群点；提供趋势线时标明方法，禁止暗示因果。
- **资源轨道/Gantt：** 适合日内排班与资源占用；时间轴统一、冲突可见、任务可键盘选择。

## 6. 组合版式

### 6.1 主图 + 时间线 + 洞察（约 6:3:3）

用于运营/实验室总览：左侧主柱图或趋势图，中部状态时间线，右侧 AI 洞察。三卡顶部对齐，主图回答“量”，时间线回答“进度”，洞察回答“为什么/下一步”。

### 6.2 主比较图 + 2×2 环形 KPI（约 7:5）

用于临床绩效：左侧 6 个月分组柱图，右侧 4 个环形 KPI。KPI 卡只放关键指标，避免与主图重复同一数字。

### 6.3 分段环图 + 水平容量条（约 1:1）

用于状态构成与资源利用：左侧回答“由什么组成”，右侧回答“哪里最高/接近阈值”。两卡共享同一状态语义，但不得为了视觉呼应擅自让每条容量条和彩色环段一一对应。

### 6.4 月历 + 当日队列（约 4:8）

用于排期：月历负责日期选择与汇总，当日时间线/资源轨道负责具体任务。月历不是装饰卡，选中日期必须驱动右侧内容并向屏幕阅读器播报变化。

桌面仪表盘首屏建议最多 4–6 个图表/数据模块，其中 1 个主图、2–3 个辅助图和 1 个例外/洞察区。表格为主任务时减少图表数量。

## 7. 交互与动效

- Hover 只强化当前 mark 与相关轴标签，其他序列可降至 35–50% 不透明度；不要让整卡跳动。
- Tooltip 使用同主题表面、1px 边框、8px 圆角和 `--ca-shadow-float`；显示维度、值、单位、比较值、状态和缺失原因。
- Tooltip 不能是唯一的数据入口。键盘用户可通过焦点、数据表或图表摘要访问相同信息。
- 点击图例切换序列、点击柱/点筛选明细时，必须显示选中状态并提供清除筛选。
- 图表更新时尽量保持坐标与上下文稳定；数字过渡不超过 200–300ms。
- 柱从基线进入，线按路径轻微揭示，环形进度最多一次绘制；不循环播放。
- 遵守 `prefers-reduced-motion`，减少动画后立即显示最终状态。
- “查看全部”、更多菜单和图表筛选器使用 Lucide 图标，遵守项目图标系统与可访问标签。

## 8. 响应式

### ≥1440px

- 使用 12 列网格；主图 7–8 列，辅助 4–5 列。
- 图例可放 Header 右侧；绘图区 240–300px。

### 1024–1439px

- 组合模块可从 3 列变 2 列；时间线或洞察移到下一行。
- 减少 X 轴标签密度，不减少数据点；允许标签隔项显示和 Tooltip 精确读取。

### 768–1023px

- 主次卡纵向排列；环形 KPI 维持 2×2，空间不足改紧凑 KPI 列表。
- 图例移到 Plot 下方或使用直接标注；表格/时间轴可水平滚动。

### <768px

- 单列，卡片内边距 12–16px；Plot 高 200–240px。
- 分组柱周期较多时使用水平滚动并冻结 Y 轴，或切换可发现的时间范围控件；不压缩到不可读。
- 环图图例改为下方单列；水平容量条仍保留左标签与右数值。
- 月历可改周视图/日列表，但所有日期与事件保持可达。
- Tooltip 采用点击/焦点触发的 Popover 或底部 Drawer，避免依赖 hover。

## 9. 可访问性

- 图表容器使用可理解的标题与说明，并提供一句结论性摘要，例如“5 月入院量最高，为 86，较 4 月增长 12%”。
- 提供屏幕阅读器可访问的数据表、明细列表或下载入口；复杂 SVG 不要求逐节点朗读，但必须有等价信息。
- 序列除颜色外使用线型、点型、直接标签、排序或文字状态区分。
- 普通正文对比度至少 4.5:1；大文字与非文字关键图形至少 3:1。浅网格可以更弱，但关键 mark 与背景必须可辨。
- 交互 mark、图例按钮、日期格和筛选器可键盘访问，焦点环使用全局 `--ca-focus`。
- 图标按钮必须有 `aria-label` 和 `title` 或 Tooltip；装饰图标 `aria-hidden="true"`。
- 图表变化由用户操作触发时，通过 `aria-live="polite"` 播报范围、筛选与摘要变化，避免逐点播报。

## 10. 数据真实性与状态

### 10.1 真实性

- 不平滑越过真实值，不把缺失补成 0，不把预测画成实线，不把相关性写成因果。
- 截断坐标、对数轴、累计值、滚动平均、标准化或指数化必须明确标注。
- 比例和环图必须验证分母；堆叠数据必须验证各段可相加；时间序列必须验证时间间隔。
- 排序、筛选和时间范围必须与图标题/摘要同步更新。
- 示例数据应包含自然波动、小数、峰谷、临界值和少量缺失，不让所有数据完美上升。

### 10.2 状态

- **Loading：** 保留标题和卡片尺寸，使用与最终图形大致对应的低对比 Skeleton，不播放无限强闪烁。
- **Empty：** 说明当前范围没有数据，并提供调整范围、清除筛选或添加数据的下一步。
- **No result：** 保留已启用筛选摘要和“一键清除”。
- **Error：** 说明无法加载的模块、最近成功更新时间和重试入口；不显示伪造的 0。
- **Partial：** 明确缺失区间/来源，并在图上使用断线、空标记或阴影区。
- **Stale：** 显示“更新于…”并降低自动决策权重，不把过期数据当实时状态。

## 11. 实现约束

- 优先继承项目已有图表库。没有图表库时，简单环图/进度条可用 CSS 或语义化 SVG；复杂坐标、缩放和交互使用成熟图表库。
- 不把库的默认主题直接带入产品。所有字体、字重、色彩、轴线、圆角、Tooltip 和状态都映射到 `calm-admin-tokens.css`；确认 Plus Jakarta Sans 400/500/600/700 已实际加载。
- SVG 使用 `currentColor` 或 CSS 变量；Canvas 图表必须额外提供 DOM 摘要和数据表。
- 图标只使用 Lucide，按图标单独导入；默认 18px，紧凑模块 16px，`strokeWidth=1.8`。
- 图表组件接收结构化数据、格式化器、单位、范围、阈值和状态，不把业务值硬编码进绘制逻辑。
- ResizeObserver 或库自带响应式机制必须避免无限重排；卡片不可见时暂停高频更新。
- 实时图表限制点数并采用窗口/抽样策略；抽样方法必须可追溯，关键异常点不得被平均掉。

推荐共享原语：`ChartCard`、`ChartHeader`、`ChartLegend`、`ChartTooltip`、`ChartState`、`ChartSummary`、`GroupedBarChart`、`StackedBarChart`、`TrendLineChart`、`KpiRing`、`SegmentDonut`、`CapacityBars`、`MonthCalendar`、`StatusTimeline`。

## 12. 反模式

- 为了“丰富”在一个仪表盘堆叠柱、折线、饼、雷达、仪表盘、地图等所有图形。
- 把普通类别涂成红黄绿，让用户误以为是风险等级。
- 使用高饱和彩虹、3D 饼图、厚重阴影、霓虹发光或玻璃拟态。
- 用双轴制造虚假相关，用平滑曲线制造不存在的峰谷，用面积大小夸大差异。
- 柱图不从 0 开始却不说明；环图分母不明；堆叠段并非同一总量。
- 每个点都显示标签造成重叠，或者只在 Hover 中提供关键数值。
- 隐藏 0、缺失、异常值或小类别来获得“更干净”的图。
- 窄屏直接删序列、删日期、删事件或删图例，而没有完整替代入口。
- 图表卡没有时间范围、单位、摘要、数据状态或明细入口。
- AI 洞察只写结论，没有证据、更新时间和人工操作。
