## 1. 设计性格

使用以下五个词判断每一个设计决策：

- **Calm 静谧**：危急信息很醒目，但整体界面不喊叫。
- **Clinical 临床**：精确、可信、讲究证据链。
- **Dense 高密度**：同屏承载多维数据，但保持可扫读。
- **Connected 连续**：调度、档案、实验室和人员像同一个工作空间。
- **Intelligent 内联智能**：AI 在任务内部给出提醒，不夺走主流程。

视觉优先级为：业务结果 > 例外与风险 > 下一步操作 > 趋势与解释 > 装饰。

## 2. 互斥主题模式

一次生成只选择一个全局主题。浅色和深色不得在同一页面状态中同时出现。

### 2.1 浅色主题（默认）

用于导航、列表、表格、档案、排期、管理和分析。采用接近白色的冷灰背景、白色卡片、细边界、极弱阴影。这是默认模式。

没有明确主题信号时，必须选择浅色。AI 洞察、监控、影像和数字孪生在浅色主题中也使用浅色语义表面，不得为了强调而临时切成深色卡片。

### 2.2 深色主题（按需）

仅在以下任一条件成立时选择深色：

- 用户明确要求深色模式或深色页面。
- 输入数据显式包含深色模式按钮或深色激活状态。若同时带有对应色号，使用这些色号。

深色主题覆盖整个应用外壳和所有业务组件，包括 Sidebar、Topbar、Page、Card、Table、Dialog、Tooltip 与专业工作区。采用深海军蓝、青绿生命信号、精密边界和高对比文字；禁止保留白色导航、白色卡片或浅色表格。

当输入提供深色色号时，优先将其映射到背景、表面、边界、文字、主操作和语义状态 Token。只有缺失的 Token 才使用本规范的默认深色值。

### 2.3 主题切换

仅在用户或数据明确要求主题切换时实现切换控件。任一时刻只允许一个根级主题生效；不并排预览浅色与深色，不以“浅色外壳 + 深色模块”表达层级。输入只说明“支持切换”但没有当前状态时，初始状态仍为浅色。

两种主题共用同一字体家族、间距网格、圆角、组件结构、交互逻辑和状态语义。

| --ca-surface-subtle | #F8FAFC | 分组、表头、次级区 |

| --ca-ink-3 | #667085 | 帮助文本 |
| --ca-line | #E4EAF1 | 边框、分割线 |

### 3.2 交互与语义色

| 语义 | 主色 | 浅底 | 使用方式 |
|---|---:|---:|---|
| Primary | #4C6CDA → #3E5ABD → #3145A7 | #EEF1FF | 主按钮、高强调入口；纯色中点用于链接与焦点 |
| AI / Intelligence | #6857F5 | #F0EEFF | AI 入口、智能洞察 |
| Healthy / Success | #13B981 | #E8F8F2 | 正常、完成、健康 |
| Info / Live | #0EA5C6 | #E7F8FC | 实时、信息态 |
| Warning | #F59E0B | #FFF7E5 | 需注意、即将超时 |
| Critical | #F0445A | #FFF0F2 | 严重、危急、失败 |

限制同屏强色。正常页面不超过 1 个主操作强色、3 个语义强调色。其他地方使用浅底标签。

### 3.2.1 主蓝渐变

主色以参考按钮取样的同色系蓝色渐变为品牌签名：

- 起点：`#4C6CDA`。
- 中点/纯色回退：`#3E5ABD`。
- 终点：`#3145A7`。
- 默认方向：`105deg`，色标为 `0% / 52% / 100%`。
- 推荐 CSS：`linear-gradient(105deg, #4C6CDA 0%, #3E5ABD 52%, #3145A7 100%)`。
- Hover：`#4563CA → #334CA9 → #2B3C96`；Active 可进一步压暗，但不得改变色相。
- 白色小字在最浅色标 `#4C6CDA` 上的对比度约 4.7:1，可用于常规按钮文字；若实现后因透明度、叠色或图片背景导致不足，必须压暗起点或改用纯色中点。

只在主按钮、Topbar 高强调 AI 入口、当前高优先级功能入口和小面积品牌头像中使用完整渐变。普通链接、图标、焦点环、图表折线、坐标轴、标签文字和大面积背景使用 `#3E5ABD` 或语义纯色，不给文字本身填渐变。每个视口区域优先只出现 1 个渐变主操作；不要把每张 KPI 卡、导航项或进度条都做成渐变。

浅色与深色主题共享同一组品牌渐变色标，以保持识别一致。深色主题中的文本链接和焦点使用更亮的纯色 Primary Token，渐变填充仍需保证白字对比度。若输入提供明确品牌色号，只在全局 Token 层整体替换，并保持三色标同色相、明度从左到右收束。

需要视觉核对时查看 [主蓝渐变参考](../assets/theme-references/01-primary-blue-gradient.png)。

## 4. 字体与排版

使用 Plus Jakarta Sans 作为全局拉丁文字与数字字体，以其友好的人文无衬线气质承载标题、控件和高密度临床表格。字体栈固定为 `"Plus Jakarta Sans", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`；中文字符由 PingFang SC / Microsoft YaHei 按字形回退，不再把 Inter 作为默认替代。数字启用 tabular numbers。

项目必须通过本地字体资源、框架字体管线或受控 Web Font 加载 Plus Jakarta Sans 的 400、500、600、700 四个字重，并设置 `font-display: swap`。不要只写字体名却不加载字体；不要使用 variable font 中未测试的中间字重，也不要由浏览器伪造粗体或斜体。

| 角色 | 字号/行高 | 字重 | 约束 |
|---|---|---:|---|
| 页标题 | 24/32 | 700 | 每页仅 1 个 |
| 区块标题 | 16/24 | 600–700 | 短句，不超过两行 |
| 卡片标题 | 14/20 | 600 | 与辅助操作同一标题行 |
| KPI 数值 | 26–32/36 | 700 | 统一小数位和单位 |
| 正文 | 14/22 | 400–500 | 每行 45–75 字符 |
| 表格/控件 | 12–14/18–20 | 500–600 | 优先可扫读 |
| Eyebrow/辅助 | 10–12/16 | 600 | 可用字距 0.08em |

核心 UI 字号以 13–34px 为主；图表轴标、Eyebrow 与法律/辅助信息可按需降至 10–12px，但必须保证对比度与可读性。正文使用 400，交互和表格使用 500，区块/按钮使用 600，页标题与关键数字使用 700。不要使用 650 等未加载字重。

Plus Jakarta Sans 自带圆润、开放的字形，后台内部无需再混入优雅衬线斜体或另一套“科技字体”。仅在用户明确提供品牌展示字体时，才允许展示层例外；数据表格、表单、图表和导航始终使用本字体栈。

需要视觉核对时查看 [Plus Jakarta Sans 字体参考](../assets/theme-references/02-plus-jakarta-sans-typography.png)。

## 5. 间距、尺寸与网格

使用 4px 基础单位和 8px 主节奏：4、8、12、16、20、24、32、40、48。优先使用 8、12、16、24、32。

- Sidebar：224px；紧凑模式 72px。
- Topbar：60px。
- 页面水平内边距：1440px 桌面下 24px；大屏 32px；小屏 16px。
- 页面最大内容宽度：1600px，数据型页面可占满剩余宽度。
- 卡片内边距：16px；主工作区 20–24px。
- 卡片间距：12–16px；主区块间距：20–24px。
- 标准控件高度：32px；主操作 36px；表格行 44–52px。

12 列网格下：KPI 卡默认 3 列/卡；主次内容默认 8:4 或 7:5；对象详情默认 4:8 或 3:6:3。

## 6. 边框、圆角与阴影

- 小控件：6px 圆角。
- 按钮、输入框：8px 圆角；状态胶囊可用 999px。
- 标准卡片：10–12px 圆角。
- 大型专业工作区：16px 圆角。
- 展示型外框：24–32px 圆角，只用于整页效果展示，不放入真实后台内部。
- 边框：1px --ca-line。
- 阴影：优先 0 1px 2px rgba(16,24,40,.04)；浮层可用 0 8px 24px rgba(16,24,40,.08)。

不使用阴影同时表达层级和装饰。大多数层级由背景与边界完成。

## 7. 应用外壳

### Sidebar

- 顶部放置品牌和产品名，主导航按业务分组，底部固定当前用户。
- 导航项高 36px，左右内边距 10–12px，图标 16px。
- 浅色主题选中项使用极浅蓝底、蓝色图标和深色文字；深色主题使用深蓝选中底、亮蓝图标和浅色文字。
- 红色数量徽标仅表示异常或待处理；普通未读使用蓝色。

### Topbar

- 左侧保留面包屑和页标题关系；右侧依次放全局搜索、AI 入口、通知和用户菜单。
- 不在每页改变 Topbar 结构。
- AI 按钮作为 Topbar 主入口时使用统一主蓝渐变；作为普通次级入口时使用 AI 紫色浅底。不得同时出现两个争夺注意力的填充强按钮，也不做大面积发光。

### Page Header

在一行内容纳页标题、一句说明和 1–2 个页级操作。页头不做 Hero，总高度尽量控制在 80px 内。

## 8. 基础组件

### KPI 卡

使用统一结构：紧凑图标盒 → 主数值与标签 → 对比、目标或分母。一行优先 4 张，数量不超过 6。不要为每张卡使用大面积不同背景色。

KPI 图标必须像参考图中的小型辅助标识，不得成为卡片主视觉：

- 标准桌面图标盒固定为 `40 × 40px`，紧凑卡可用 `36 × 36px`；圆角 8–10px，使用低饱和语义浅底。
- 图标本体固定为 `18 × 18px`；特别紧凑时用 `16 × 16px`，页级功能入口最多 `20 × 20px`。KPI 卡内禁止使用 24px 以上图标。
- 图标本体统一 `stroke-width: 1.8`、`currentColor`、无填充；图标盒与卡片边缘至少保留 12px 间距，图标不得贴边、顶边或占满色块。
- 图标盒和 SVG 必须使用两个独立元素与 class。容器只控制盒尺寸、背景、圆角和居中；SVG 只控制图标尺寸与描边。禁止把 `width: 36–48px; height: 36–48px` 的容器 class 直接赋给 SVG。
- 在 Vanilla 项目使用图标占位符时，把 `data-lucide-icon` 放在容器内的子元素，不要放在容器本身，避免 hydrate 后 SVG 继承容器尺寸。
- 推荐排列为左侧图标盒，右侧先主数值、后指标名称；若沿用输入界面的“标签在上、数值在下”，仍必须保持同样的图标比例与留白。

推荐实现：

```html
<span class="kpi-icon-box">
  <span class="icon" data-lucide-icon="users" data-icon-size="18"></span>
</span>
```

```css
.kpi-icon-box {
  display: grid;
  width: 40px;
  height: 40px;
  flex: 0 0 40px;
  place-items: center;
  border-radius: 9px;
  background: var(--ca-primary-soft);
  color: var(--ca-primary);
}
.kpi-icon-box > .icon { width: 18px; height: 18px; }
```

### 按钮

- Primary：统一 `105deg` 主蓝渐变 + 白字 + 深端细边框，使用 600 字重；每个视口区域优先仅 1 个。Hover/Active 只压暗同一蓝色色阶，不换色相。
- Secondary：白底深字 + 细边框。
- Tertiary：文本或淡底，用于“查看全部”“打开档案”。
- Destructive：默认红字浅底；仅确认操作使用红底。

### 标签和状态

高度 20–24px，字号 11–12px，使用浅底、深字和小圆点/图标。标签写明确状态：“已完成”“等待结果”“危急”，不只写“异常”。

### 表格

- 将高频筛选和搜索放在表格正上方。
- 表头可使用浅灰底，数字列右对齐，文本列左对齐。
- 将主对象放第一列，保留次要 ID 或元数据。
- 使用行级菜单收纳低频操作，不在每行堆叠多个强按钮。
- 提供 loading、empty、error、no-result 四种状态。

### 筛选器

优先显示 3–5 个高频筛选，其余收入“更多筛选”。展示已启用条件数量，并提供一键清除。

### AI 洞察卡

必须包含：类型/风险等级、结论、证据或触发原因、更新时间、相关对象、可操作的下一步。浅色主题使用白卡与浅紫标识；深色主题使用当前深色表面与紫色标识。AI 卡不得切换到与全局不同的主题，强调“建议”而非“自动决策”。

### 人员卡

显示头像、姓名、专科/职位、在岗状态、当日负荷和 1–2 个快捷操作。使用相同卡高，不因个别文案造成瀑布流。

### 浮层与覆盖组件

下拉菜单、Popover、Tooltip、Dialog 和 Drawer 必须与页面主体使用同一全局主题与组件语言：

- 使用 `--ca-surface` 背景、`--ca-line` 边框、`--ca-ink`/`--ca-ink-2` 文字和 `--ca-shadow-float` 阴影；圆角沿用控件 8px、卡片 10–12px 的体系，不使用浏览器默认浮层样式。
- 下拉菜单和 Popover 从触发器边缘对齐，默认间距 4–8px；宽度由内容决定并设置合理的最小/最大值，超出视口时自动翻转或平移，不被卡片 `overflow` 裁切。
- 菜单项保持统一高度、图标尺寸与左右内边距，并实现 default、hover、active、selected、disabled、danger 和 focus-visible 状态。危险项只使用语义红色，不把整张菜单染红。
- Dialog 和 Drawer 必须有明确标题、关闭入口、遮罩、焦点锁定、Esc 关闭和关闭后的焦点恢复；主要操作与页面按钮层级一致。
- 浮层只改变信息的交互承载形式，不得删除、概括或改写原始菜单项、字段、说明和操作。收入“更多”菜单的信息必须保持清晰命名、可发现且键盘可达。
- 浅色页面只使用浅色浮层，深色页面只使用深色浮层；禁止复制第三方组件默认样式形成局部异色主题。

## 9. 数据可视化

凡页面包含图表、日历、时间线、容量进度或数据洞察，必须完整读取 [chart-design-system.md](chart-design-system.md)。先写出业务问题，再选择能最快回答问题的图：

- 趋势：折线图或面积图。
- 同单位周期比较：圆角分组柱图；真实组成才使用堆叠柱。
- 排名与容量：水平条形图、进度条或 Bullet chart。
- 单指标进度与阈值：环形 KPI 或带目标线的进度条。
- 构成：仅在 5 类以内使用分段环图，超过 5 类改为排序条形图。
- 调度与流程：月历、状态时间线或资源轨道。
- 高密度二维模式：单色连续色阶热力图，并提供精确文本等价信息。

图表卡共享统一标题行、时间范围、单位、图例/直接标注、Tooltip、文本摘要、明细入口和 loading/empty/error/no-result 状态。使用主蓝、紫色、青色作为普通序列；Success、Warning、Critical 只表达真实业务状态或阈值。渐变只允许同色系低对比，且不得暗示不存在的堆叠、连续性或风险。不要使用 3D 饼图、装饰性双轴、无意义面积渐变或彩虹配色。

同一仪表盘优先复用 2–3 个图表族。图表只是辅助时保持 160–240px 紧凑高度；主图通常 220–300px。图表不得挤压主任务表格，也不得为了移动端整洁删除序列、日期、事件或图例。

## 10. 专业工作区

使用以下固定层级：

1. 顶部：对象身份、时间/数据新鲜度、视图切换、总体指数。
2. 中部：主影像或监测画布，使用细线网格、定位标记和可点击节点；所有颜色服从当前全局主题。
3. 悬浮信息：相关器官/信号的状态、证据、量化指标与进入详情入口。
4. 底部：图例、操作提示、数据源或同步时间。

目标是“精密医疗设备界面”，不是“科幻游戏 HUD”。浅色主题使用冷白表面和低对比网格；深色主题使用深色表面和青绿信号。保留信息可读，避免大量装饰网格和无功能数字。

## 11. 状态与文案

状态文案同时回答“发生了什么”和“下一步是什么”。使用中性、精确、不责备用户的语气。

- 好：“3 项检验结果等待复核”。
- 差：“出错了！”
- 好：“过去 7 天未就诊率上升 8%，查看影响时段”。
- 差：“AI 发现重大问题”。

## 12. 动效与反馈

- Hover：120–160ms；按钮使用背景/边框转换，卡片最多上移 1px。
- 展开、抽屉、切换：180–240ms。
- 页面级转场通常不需要；使用局部 skeleton 保留上下文。
- 实时信号可用低频率脉冲，只作用于 6–8px 状态点。
- 支持 prefers-reduced-motion，不让临床警报依赖闪烁。

## 13. 响应式与可访问性

- ≥1440px：完整 Sidebar + 4 列 KPI + 双列/三列工作区。
- 1024–1439px：收紧 Sidebar 或图标模式；KPI 2–4 列；次要侧栏可改抽屉。
- 768–1023px：导航抽屉；KPI 2 列；主次区块纵向排列。
- <768px：单列；表格使用水平滚动、列管理或卡片化，不把所有列挤成难读文本。

保证正文对比度至少 4.5:1，大文字 3:1；所有操作可键盘访问；焦点环清晰；图表和状态提供文本等价信息；触控目标尽量不小于 40px。

## 14. 反模式

- 为了版式简洁删除、概括、合并、改名或重新分组原始信息。
- 在响应式布局中直接删列、删字段或删操作，而没有提供菜单、抽屉、列管理或横向滚动等完整访问方式。
- 下拉菜单、Popover、Dialog 或 Drawer 使用与全局字体、颜色、圆角、边框和阴影不一致的默认样式。
- 一页同时出现五种高饱和卡片背景。
- 在浅色页面中嵌入深色 AI 卡、深色监控面板或深色专业工作区。
- 在深色页面中保留白色 Sidebar、白色卡片或浅色表格。
- 数据卡全部使用不同渐变。
- 主蓝渐变被改成多种方向/色标，铺满大卡片或用于渐变文字；按钮之间无法形成稳定品牌识别。
- 只在 CSS 中声明 Plus Jakarta Sans 却没有加载 400/500/600/700，或混入 Inter、衬线体、伪造字重造成页面字形跳变。
- 只为“高级感”将整个界面切换为深色，而没有用户要求或输入数据依据。
- 把警告色用于装饰，导致真实异常失去优先级。
- 只显示 KPI 大数，不给基准、趋势或分母。
- 所有卡片都能点，却没有 hover、focus 和明确操作。
- 将业务表格做成无表头的漂亮卡片堆，牺牲扫读效率。
