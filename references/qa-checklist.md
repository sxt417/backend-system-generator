# 静谧临床后台·交付验收清单

交付前逐项检查。出现任何“不是”时，先修复再交付。

## 零、内容保真与结构保护

- [ ] 是否在设计前完整盘点了原始导航、模块、分组、层级、标题、说明、字段、数值、单位、状态、标签、表格列、Tab、按钮、操作入口和辅助信息？
- [ ] 是否建立并核对了“原始信息 → 新界面位置”的一对一映射，所有原始信息均完整可见或可通过明确交互访问？
- [ ] 是否保持了原有模块顺序、信息分组、父子层级、业务语义、表格字段和导航关系，没有因样式而擅自重组？
- [ ] 交互形式调整后，是否仍保留全部原始文案、信息和功能，且没有增加不必要的访问步骤？
- [ ] 响应式适配是否仅改变排列与承载形式，没有直接删列、删字段、删状态或删操作？
- [ ] 如存在内容精简、合并、改写或结构调整，是否取得用户明确授权并在交付中逐项说明？

## 一、产品结构

- [ ] 是否明确了当前用户、核心任务和高风险信息？
- [ ] 是否只选用一个主页面模板？
- [ ] 页面是否在首屏给出最需处理的信息？
- [ ] 主操作是否唯一、明确且与当前任务相关？
- [ ] AI 洞察是否有证据、更新时间和下一步操作？

## 二、全局一致性

- [ ] 是否只渲染一个全局主题，没有浅色与深色模块混搭？
- [ ] 没有主题信号时是否使用浅色默认主题？
- [ ] 如使用深色，是否有用户要求或输入数据中的深色按钮/状态作为依据？
- [ ] 深色主题是否优先采用输入提供的对应色号，并覆盖 Sidebar、Topbar、Card、Table 与弹层？
- [ ] Sidebar、Topbar、Page Header 的尺寸和顺序是否与其他页一致？
- [ ] 是否只使用一套字体、图标、圆角、边框和阴影？Plus Jakarta Sans 的 400/500/600/700 是否真实加载，并由中文字体按字形回退？
- [ ] 主按钮与高强调入口是否统一使用 `105deg`、`#4C6CDA → #3E5ABD → #3145A7` 的主蓝渐变，没有局部改方向、换色标或新增另一套主色？
- [ ] 同一业务状态是否使用同一文案、颜色和图标？
- [ ] 页面是否复用共享组件，而不是复制后各自改样式？
- [ ] 所有卡片标题行、“查看全部”和行级菜单是否位置一致？

## 三、视觉层级与主题

- [ ] 浅色主题是否以冷白/浅灰为主，深色主题是否以深色语义表面为主，且强色数量受控？
- [ ] AI、影像、监控和专业工作区是否服从当前全局主题，没有使用异色主题强调？
- [ ] 是否主要使用字号、字重、间距和对齐建立层级？
- [ ] 除统一的同色系主蓝渐变外，是否没有多色渐变、玻璃拟态、霓虹光晕和浓重阴影？
- [ ] 渐变是否只用于小面积主操作/高强调入口，没有用于正文、链接、坐标轴、大片卡片背景或普通状态？
- [ ] 小文字、边框和次要信息的对比度是否仍然可读？
- [ ] 主蓝渐变上的白色文字是否在最浅色标仍达到至少 4.5:1，Hover、Active、Disabled 与 Focus 是否完整？

## 四、数据和组件

- [ ] KPI 是否有单位、基准/目标、时间范围或趋势？
- [ ] KPI 是否采用独立的 36–40px 图标盒与 16–18px 图标本体，SVG 没有继承图标盒的宽高、没有贴边或占满色块？
- [ ] 是否在浏览器 100% 缩放下检查了 KPI 图标的 computed size，确认常规 KPI 图标不超过 18px、页级功能入口不超过 20px？
- [ ] 表格是否将主对象放在第一列，数字右对齐，且有排序/筛选？
- [ ] 是否先明确了每个图表要回答的一个主问题，并从 `chart-design-system.md` 选择了匹配图表族？
- [ ] 图表是否有标题、单位、时间/数据范围、图例或直接标注、Tooltip、文本摘要与明细入口？
- [ ] 普通序列色与业务状态色是否分离，Warning/Critical 是否只表示真实阈值或异常？
- [ ] 柱图是否从 0 开始或明确标出断轴？堆叠数据是否真实可相加？环图是否有明确分母且类别不超过 5 个？
- [ ] 折线是否没有跨越缺失值、没有用平滑制造不存在的峰谷，并将预测段明确标为预测？
- [ ] 不同单位是否使用小多图；如使用双轴，是否标清单位、颜色并说明必要性？
- [ ] 阈值、目标、比较周期、小数位、金额/时长单位与数据来源是否一致？
- [ ] 同一仪表盘是否复用 2–3 个图表族，而不是为了丰富感堆满不同图形？
- [ ] 数据是否包含正常、临界、异常、缺失与空状态？
- [ ] 是否实现 loading、empty、error、no-result、partial/stale 状态，并且错误时没有伪造为 0？

## 五、交互与可访问性

- [ ] 所有可点击元素是否有 hover、active、focus 和 disabled 状态？
- [ ] 是否可以只用键盘完成核心流程？
- [ ] 焦点顺序和焦点环是否清晰？
- [ ] 状态是否不只依赖颜色表达？
- [ ] 图表序列是否还通过线型、点型、标签、排序或文字区分，并提供可访问数据表/列表？
- [ ] 图表图例、数据点、日期格和筛选是否可键盘操作，移动端是否不依赖 hover？
- [ ] 对话框、抽屉和弹出层是否有标题、关闭方式与正确焦点管理？
- [ ] 下拉菜单、Popover、Dialog、Drawer 和 Tooltip 是否复用全局主题的字体、颜色、圆角、边框、阴影、图标、状态和动效？
- [ ] 浮层是否正确对齐触发器、避免视口溢出与容器裁切，并保留原始信息和操作的完整可达性？
- [ ] 是否遵守 prefers-reduced-motion？

## 六、响应式

- [ ] 1440px 及以上是否显示完整外壳与多列布局？
- [ ] 1024–1439px 是否优雅收紧 Sidebar 和次要侧栏？
- [ ] 768–1023px 是否将主次区块纵向排列？
- [ ] <768px 时表格是否采用可理解的滚动、列管理或卡片化策略？
- [ ] <768px 时图表是否通过横向滚动、时间范围、周视图或图例重排保持数据完整，而非删序列、删日期或删事件？
- [ ] 所有断点是否没有意外溢出、标题遮挡和按钮挤压？

## 七、最终一致性快检

1. 拿掉 Logo 后，这些页面是否仍明显属于同一个产品？
2. 不看颜色时，用户是否仍能知道什么最重要？
3. 所有警告色是否都有业务意义？
4. 当前主题是否有明确选择依据，且页面内不存在另一套主题？
5. 页面是否高密度但不令人焦虑？
6. 与原始输入逐项对照时，是否做到信息零丢失、结构零擅改？
7. 所有下拉与弹窗是否看起来属于同一个产品？
