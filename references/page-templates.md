## 1. 全局页面骨架

所有后台页共享以下结构，并由一个根级主题统一覆盖。默认使用浅色；深色仅由用户要求或输入数据中的深色模式信号触发。

    应用
    ├─ Sidebar（业务分组 + 当前用户）
    └─ Main
       ├─ Topbar（面包屑/搜索/AI/通知/账户）
       └─ Page
          ├─ Page Header（标题/说明/页级操作）
          ├─ Optional KPI Strip
          ├─ Primary Workspace
          ├─ Exception / AI Layer
          └─ Supporting Modules

页面切换时仅更换 Page 内容。Sidebar 宽度、Topbar 高度、页头间距、卡片半径和内容栅格保持不变。

## 2. 经营总览模板

**适用：** 临床 Dashboard、运营总览、医院或业务单元日常驾驶舱。

**主要问题：** 今天整体怎么样？有哪些例外需要处理？

**固定结构：**

1. 首屏 4 张 KPI 卡：总量、当日量、占用/效率、收入/绩效。
2. 主视觉工作区：使用真正代表业务的高价值模块，如数字孪生、床位/资源地图或实时患者队列；视觉表面服从当前全局主题。
3. AI / 例外洞察条：3 张紧凑洞察卡，按严重性排序。
4. 两列模块：实时指标 + 今日日程。
5. 两列模块：长期趋势（折线/分组柱）+ 效率指标（环形 KPI/Bullet）。
6. 底部模块：状态构成（≤5 类分段环图）+ 科室/品类排名（水平容量条）。

**一致性规则：** KPI 卡等高；图表卡共享标题行、时间范围、单位、Tooltip 与状态；“查看全部”在相同位置；AI 卡不和普通 KPI 抢主色。图表实现遵守 [chart-design-system.md](chart-design-system.md)。

**避免：** 只放八张大数字卡、每张卡不同渐变、主屏没有可操作的异常。

## 3. 对象详情模板

**适用：** 患者档案、客户详情、设备详情、订单详情、病例记录。

**主要问题：** 这个对象是谁？现在状态如何？最近发生了什么？

**固定结构：**

1. 身份头卡：头像/主标识、名称、ID、主状态、关键属性、“添加记录”等主操作。
2. 页内 Tab：概览、体征/指标、用药/配置、检验/记录、影像/附件、备注。
3. 主内容区：左侧 4/12 展示可视化对象；中部 5/12 展示当前指标和主问题；右侧 3/12 展示警报、药物/标签和责任人。
4. 下方两列：访问/事件时间线 + 指标趋势。

**变体：** 如无可视化对象，使用 8:4 主次布局，主区为记录，侧区为属性和关系。

**一致性规则：** 所有详情页的身份头卡、Tab 和时间线必须复用同一组件。

## 4. 时间调度模板

**适用：** 预约排程、诊室排班、资源预订、工单时间轴。

**主要问题：** 今天谁在什么时间做什么？哪些时段冲突或待确认？

**固定结构：**

1. 4 张 KPI：今日预约、待处理、已确认、新申请。
2. 左侧 8/12：日时间线或资源轨道，展示时间、对象、任务、地点与状态。
3. 右侧 4/12：月历、当日汇总、待接受请求；日期格与底部汇总遵守图表规范中的“月历 + 汇总条”。
4. 将“可预订时段”直接置于时间线中，使用浅色虚线块。

**关键交互：** 日/周/月切换、按资源筛选、时段直接新建、请求一键接受、冲突解释。

**一致性规则：** 预约状态颜色与列表页、详情页完全一致。

## 5. 高密度队列模板

**适用：** 实验室订单、检测结果、审核队列、质量问题、工单或告警中心。

**主要问题：** 哪些必须先处理？队列在哪里堵住？

**固定结构：**

1. 4 张 KPI：今日总量、等待结果/处理、危急项、周转合规率。
2. 筛选工具条：搜索、状态、优先级、部门、日期、列设置。
3. 主表格：业务对象、关联对象、负责人、优先级、分类、状态、时间。
4. 底部 6:3:3：负荷趋势（同色阶堆叠柱/折线）、处理时间线、AI 例外建议。

**关键交互：** 排序、批量处理、固定关键列、行展开、保存视图、导出。

**一致性规则：** 表格是主角，不用大图表把队列压到首屏以下。

## 6. 人员资源模板

**适用：** 医生与员工、客户成功团队、坐席管理、项目成员。

**主要问题：** 谁在岗？谁负荷过高？谁适合处理当前需求？

**固定结构：**

1. 4 张 KPI：总人数、在岗、关键职能数、当前繁忙。
2. 工具条：搜索、部门、在岗状态、视图切换、新增人员。
3. 三列等高人员卡网格；窄屏改两列/单列。
4. 人员卡显示身份、部门/职称、对象总数、当日工作量、质量评分、在岗标签、排期/消息操作。

**变体：** 当人数 >50 时默认使用表格，卡片仅用于主要人员、匹配结果或监控对象。

## 7. 专业工作区模板

**适用：** 数字孪生、影像工作台、实时监控、网络拓扑、风险地图。

**主要问题：** 当前对象哪个部位/节点需要关注？变化是什么？

**固定结构：**

1. 顶部标题区保留对象名、ID/时间、视图 Tab 和总体健康/风险指数，容器服从全局浅色或深色主题。
2. 中间为一个或双视图主画布，使用当前主题下可读的细线轮廓、定位圆环、弱网格和局部信号点。
3. 点击节点后就近弹出紧凑信息卡，包含名称、风险、证据、数值和查看详情。
4. 底部图例只保留 Healthy / At Risk / Critical 等业务状态。

**主题方式：** 默认使用浅色版本。仅当用户明确要求深色，或输入数据包含深色模式按钮/激活状态时，整个应用外壳与专业工作区一起切换为深色；若数据提供对应色号，优先采用。禁止浅色 Sidebar/Topbar 搭配深色工作区。

## 8. 标准列表与设置模板

**适用：** 账单、药房、报表、通知、角色权限、集成、字典与基础设置。

### 列表型

1. Page Header + 主操作。
2. 紧凑工具条。
3. 表格/分组列表。
4. 批量操作条在选中后出现。
5. 右侧抽屉承载编辑或详情，避免为轻量任务频繁跳页。

### 设置型

1. 页内左侧二级导航 200–240px。
2. 右侧表单宽度 640–760px，分为明确的设置组。
3. 保存操作固定在页面底部或表单末尾，维持同一策略。
4. 危险操作与常规设置分区，使用文案说明影响。

## 9. 模板组合规则

- 一页只选 1 个主模板，可从其他模板引入 1–2 个辅助模块。
- 不把 Dashboard 的 KPI 带强行放入每一个设置页或对象详情页。
- 不把人员卡网格用于超过 50 个对象的高密度浏览。
- 不为强调局部模块而切换主题；专业工作区、普通表格、表单和设置页始终服从同一个全局主题。
- 如页面同时存在“监控”和“处理”，让监控占 7/12、处理占 5/12；不做无理由的对称。
- 默认主题为浅色。深色主题必须记录触发依据与色号来源，并覆盖整个应用外壳。
- 若实现主题切换，任一时刻只显示一个主题状态，不并排、不混搭。
- 所有模板复用同一套 Card、KpiCard、StatusBadge、FilterBar、DataTable、PageHeader、AiInsightCard 原语组件。
- 所有图表模板复用 ChartCard、ChartHeader、ChartLegend、ChartTooltip、ChartState、ChartSummary，并从 [chart-design-system.md](chart-design-system.md) 选择具体图表族。
